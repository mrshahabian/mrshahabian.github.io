SECTION 01 · FUNDAMENTALS
What is Agentic AI?
An LLM that doesn't just answer. It perceives a goal, plans steps, acts using tools, and reflects on the result, looping until the goal is done.
The LLM itself only runs at Plan and Reflect. Perceive and Act are plain code. The loop keeps turning until Reflect decides the goal is met, or a stopping rule is hit.
The building blocks of an agent
LLM core
The reasoning engine that interprets goals and decides next actions
Memory
Short-term context plus long-term stores (vector DB, files, history)
Planning & orchestration
Breaks a goal into steps; routes work across tools or sub-agents
Tools & actions
APIs, code execution, databases, search: how the agent affects the world
Perception / input
Text, voice, vision, sensor or document inputs feeding the loop
Guardrails & evaluation
Validation, human-in-the-loop checks, and monitoring of outputs

SECTION 02 · PLATFORMS
Many platforms, because there are many purposes
Some platforms design and run the whole agent lifecycle; others let you assemble pre-built agents; others are code frameworks for full control.
Full-cycle builders
Design, connect, test and deploy an entire agent visually, no code needed
Vertical / pre-built agents
Take an existing, specialised agent (e.g. voice) and plug it into your product
Code-first frameworks
Native libraries giving full control over orchestration and logic
More guided, faster to ship
More control, more effort
A fourth layer sits underneath, and increasingly across, all three: the cloud and model-provider platforms (AWS, Google, Azure, Cloudflare, OpenAI, Anthropic) covered next.

SECTION 03 · THE MODELS
Open-weighted vs. closed LLMs
Closed (API-only)
GPT-5 · Claude · Gemini
Weights never released. Access via API. Best quality & convenience, no infrastructure, but less control, ongoing cost, data leaves your premises.
Open-weighted
Llama · Mistral · Qwen · DeepSeek · Gemma
Weights downloadable. Run & fine-tune anywhere, full data control, one-off compute cost, but you own the serving & ops.

How to specialize an LLM
Increasing cost and control, left to right.
Prompt engineering
No training, instructions & examples only
RAG
Weights untouched, knowledge injected at query time
PEFT (LoRA / QLoRA)
Small adapter layers trained, base model frozen
Full fine-tuning
Every weight updated: maximum control, maximum cost

SECTION 05 · CASE STUDY
A bio-computational research agent
Goal: given a novel protein sequence, return literature-backed hypotheses about its function and off-target risks.
Platform: LangGraph
Graph of nodes: BLAST search → UniProt lookup → PubMed retrieval → synthesis
Model: BioMistral-7B
QLoRA fine-tuned on ~60k PubMed/PMC abstracts + UniProt annotations, 4-bit 
Output
Cited function hypothesis, homologous domains, and an off-target binding flag for the wet-lab team to verify
Why QLoRA here: ~14GB VRAM, <8 hours on a single A100, no multi-GPU cluster needed, yet domain-accurate terminology and reasoning.
Other specialized bio-LLMs worth knowing: BioGPT (Microsoft, biomedical text) and Evo 2 (Arc Institute, a genomic foundation model trained directly on DNA sequence, not text).

SECTION 05 · CASE STUDY
A CRISPR guide-RNA design agent
Goal: given a target gene, return ranked, ready-to-order guide RNAs, a concrete lab deliverable, not just a read.
CRISPR: a gene-editing system. An enzyme (Cas9) cuts DNA at a spot chosen by a short "guide RNA"
PAM site: a short DNA pattern the enzyme needs sitting next to its target before it can cut
On- vs off-target: does the guide cut the gene you want, or somewhere else by mistake
The agent is a thin coordinator: it calls each tool in turn and only the final ranking step runs through the LLM.
Why this is more practical: most of the work is deterministic tool calls, not LLM-generated biology, which makes it cheaper to build and easier to trust. Same pattern fits primer design, codon optimization, or epitope checks.

Key takeaways
Agentic AI is defined by the perceive → plan → act → reflect loop, not just a bigger chatbot
Platform choice is about purpose: no-code builders, vertical agents, or code frameworks each fit a different job
Cloud and model-provider platforms (AWS, Google, Azure, Cloudflare, OpenAI, Anthropic) blend all three, and suit teams already in one ecosystem
Open-weighted LLMs trade convenience for control, privacy and one-off compute cost
Ollama, vLLM and llama.cpp solve different serving problems: dev, production, and edge, and model size dictates the hardware
Specialization is a spectrum (RAG, LoRA, QLoRA and full fine-tuning); pick by budget and need
