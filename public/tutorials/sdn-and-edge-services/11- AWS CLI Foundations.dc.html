The AWS CLI

The console is great for beginners, but it's slow and manual. The command line lets you automate complex tasks — and it's the foundation for advanced DevOps work.

⏱️ ~26 min 📑 14 chapters 🧠 3 quizzes 🎯 10-step workshop
Prepared by Reza Shahabian
Chapter 01 · Why leave the console

Console vs command line

🖱️ AWS Console
• Great for beginners and for exploring
• Slow and manual — every click repeated by hand
• Hard to reproduce exactly or hand to a colleague
• Cannot be put in a script or a pipeline
⌨️ AWS CLI
• Automates complex, repetitive tasks
• Commands are shareable, reviewable text
• Scriptable — the same run, every time
• The foundation for advanced DevOps work
🔗 This is the bridge between clicking around and full Infrastructure as Code — CLI commands are the first thing you'll put inside a pipeline.
Chapter 02 · One pattern, every service

Anatomy of a command

Learn the shape once and every AWS service follows it: aws <service> <command>.

aws
the tool
ec2
service
create-vpc
command
--cidr-block 10.0.0.0/16
options
📤 Output is JSON by default
Machine-readable, so another command or script can consume it.
🔎 --query and --output trim it
Pull out just the fields you want, as table or plain text.
Part A · Verification & exploration

Prove you're connected

Nothing to install — the AWS Academy Terminal comes pre-installed and pre-authenticated with your credentials. Open the "AWS Details" panel in your Learner Lab and launch the terminal/IDE.

$ aws sts get-caller-identity { "UserId": "AROA...:user123", "Account": "123456789012", "Arn": "arn:aws:sts::123456789012:assumed-role/voclabs/user123" }
✅ You see JSON
Account and User ARN returned — you're ready to go.
⚠️ Access denied
Either your lab isn't started, or AWS Academy has restricted that command — still a useful one to know.

Part B · Practising the syntax

Your first commands

# list your buckets $ aws s3 ls # create one (the name must be globally unique) $ aws s3 mb s3://my-unique-bucket-name # see the virtual machines in your account $ aws ec2 describe-instances # build a whole VPC, from the terminal $ aws ec2 create-vpc --cidr-block 10.0.0.0/16
💡 That last command is the one to sit with — a network that would take a dozen console clicks, created in a single line you can paste into a script.

Steps 8–9 · Configure & prove it works

User data & verification

The user-data script runs on first boot — installing Apache and dropping in a page that tests the database connection.

#!/bin/bash yum update -y yum install -y httpd mysql systemctl start httpd systemctl enable httpd # a page that proves the web tier can reach RDS # replace DB_ENDPOINT with your actual RDS endpoint echo "<?php \$conn = new mysqli('DB_ENDPOINT', 'admin', '<password>', 'MyDatabase'); if (\$conn->connect_error) { die('Connection failed'); } echo 'Connected successfully to RDS!'; ?>" > /var/www/html/db_test.php
🔑 SSH in
ssh -i <key.pem> ec2-user@<Public_IP>
🌐 Then in a browser
http://<Public_IP>/db_test.php
✅ A "Connected successfully to RDS!" message proves the whole chain: public subnet → IGW → web server → peering → private RDS.
Step 10 · Don't skip this

Cleanup

Lab resources keep consuming credit until you remove them. Tear down in reverse order of creation.

aws ec2 terminate-instances --instance-ids <Instance_ID> aws rds delete-db-instance \ --db-instance-identifier MyRDSInstance \ --skip-final-snapshot aws ec2 delete-vpc --vpc-id <VPC1_ID> aws ec2 delete-vpc --vpc-id <VPC2_ID>
⚠️ A VPC won't delete while resources still live inside it — remove instances, databases, gateways and peering connections first.
