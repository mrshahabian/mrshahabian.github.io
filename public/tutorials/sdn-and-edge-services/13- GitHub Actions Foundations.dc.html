Part B · Creating the workflow

Where the file lives

Create a file in your repo at .github/workflows/deploy.yml. This YAML file defines the steps GitHub will take on your behalf.

your-repo/ ├── TestStack.yaml ← your CloudFormation template ├── README.md └── .github/ └── workflows/ └── deploy.yml ← the pipeline definition
📁 The path matters
GitHub only looks in .github/workflows/. A YAML file anywhere else is just a file.
📏 Indentation matters
YAML is whitespace-sensitive — a misaligned key silently changes the structure.

Chapter 09 · Chaining steps together

Passing values between steps

Each step runs in its own shell, so a plain variable does not survive. Append it to $GITHUB_ENV and later steps read it as an environment variable.

- name: Create VPC run: | VPC_ID=$(aws ec2 create-vpc \ --cidr-block 10.0.0.0/16 \ --query 'Vpc.VpcId' --output text) echo "VPC_ID=$VPC_ID" >> $GITHUB_ENV - name: Create Subnet run: | aws ec2 create-subnet \ --vpc-id $VPC_ID \ --cidr-block 10.0.1.0/24
🔎 --query extracts just the ID
Pull out the one value you need as plain text, rather than parsing a JSON blob.
🌱 $GITHUB_ENV carries it forward
The pipeline equivalent of the scratch file of IDs you kept during the CLI workshop.
