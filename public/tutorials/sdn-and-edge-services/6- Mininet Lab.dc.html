Stage 1 · Must pass before anything else

Verify the environment

STEP 1.1 — CONFIRM MININET RUNS
$ sudo mn --test pingall
What this does
• Creates Mininet's default topology (1 switch + 2 hosts)
• Starts a controller
• Runs a full connectivity test
• Tears the topology down
✅ Expected result
*** Results: 0% dropped
Or an equivalent success message. If this fails, your image is not ready — do not continue until it is fixed.
STEP 1.2 — CLEAN UP MININET STATE
$ sudo mn -c
🧹 Removes leftover network namespaces, OVS bridges and controller junk from previous runs. Run this whenever Mininet behaves strangely, and after any aborted session.
Stage 2 · No Python yet

Start with a built-in topology

Before writing any code, understand how Mininet behaves with a simple topology. This builds foundational understanding and avoids blind scripting.

STEP 2.1 — CREATE A SINGLE-SWITCH TOPOLOGY
$ sudo mn --topo single,2
What this creates
1 OpenFlow switch · 2 hosts (h1, h2) · both on the same switch. The simplest possible SDN topology.
Then test connectivity
mininet> h1 ping -c 3 h2
Confirms IP addressing, switch forwarding, and controller-switch communication.
STEP 2.3 — EXIT AND CLEAN
mininet> exit
$ sudo mn -c
🚦 Only after this works should you move to Python-based topologies.

Stage 4 · The pass/fail gate

Validate the custom topology

AUTOMATIC TEST
$ sudo mn --custom topo_lab_01.py --topo mytopo --test pingall
What this does
• Loads your topology file
• Builds the custom topology
• Pings between all host pairs
• Tears everything down
⚠️ Why this matters
If this fails, your topology file is wrong — and everything later becomes meaningless. Fix it here, not three stages downstream.
AFTER THE TEST, CLEAN
$ sudo mn -c

Stage 7 · Validate the bandwidth cap

Measure throughput with iperf

7.1 — START A SERVER ON h3 (BACKGROUND)
mininet> h3 iperf -s &
7.2 — RUN THE CLIENT FROM h1
mininet> h1 iperf -c h3
7.3 — STOP THE SERVER WHEN DONE
mininet> h3 kill %iperf
✅ Expected outcome
Reported throughput close to the configured limit — ≈ 10 Mbit/s.
📏 Read it honestly
It will not be exactly 10.00 — protocol overhead and timing get in the way. Near is the correct result; far off is the signal to investigate.
Stage 8 · Evidence for marking

Stable MACs & packet capture

🏷️ Use --mac for repeatable results. Without it, host MACs change between runs, making debugging and packet correlation far harder. Verify with h1 ifconfig.
INSTALL TSHARK (REQUIRED)
$ sudo apt update
$ sudo apt install -y tshark
$ tshark --version
TERMINAL 1 — RUN THE TOPOLOGY
$ sudo mn --custom topo_lab_01.py --topo mytopo --mac
THEN GENERATE TRAFFIC
mininet> h1 ping -c 5 h2
TERMINAL 2 — CAPTURE, AND SAVE A PCAP FOR EVIDENCE
$ sudo tshark -i any -f "icmp" -a duration:20
$ sudo tshark -i any -f "icmp" -a duration:20 -w icmp_capture.pcap
FROM YOUR LOCAL MACHINE — NOT THE EC2 SHELL
$ scp -i <your-key>.pem ubuntu@<EC2_PUBLIC_IP>:~/icmp_capture.pcap .
🚫 Do not run the Wireshark GUI on EC2 unless you have X11 forwarding or a desktop environment — there is no display server, so Qt will fail. Capture with tshark, export the .pcap, open it locally.
