Chapter 01 · The core idea

What is Infrastructure as Code?

IaC automates the management of IT infrastructure by treating it as software. Instead of manual configuration, everything is scripted and automated.

🖱️ Manual (ClickOps)
• Point-and-click through the console
• Slow, repetitive, easy to mis-configure
• "It works on staging" — but nobody knows why
• No history of who changed what
📜 Infrastructure as Code
• Rapid delivery of infrastructure services
• Consistency and reduced errors
• Increased productivity
• Version-controlled, reviewable, repeatable
🏢 Why it matters: organisations need efficient, scalable infrastructure as they shift to digital — and you cannot scale a process that depends on someone remembering which buttons to press.

Chapter 05 · The only constant

Optimising for change

Change is inevitable in any infrastructure. IaC optimises your ability to manage those changes rapidly and safely.

🙅 "Automation is too risky"

The opposite is true — automation ensures safe, reliable changes. Manual steps are where mistakes creep in.

🙅 "We'll automate later"

Automation should be built from the start. Retrofitting it onto a hand-built estate is far harder than starting with it.

✅ Treat the ability to change as a feature of your infrastructure, not a threat to it.

Chapter 07 · IaC on AWS

Meet AWS CloudFormation

CloudFormation lets you define AWS infrastructure using templates written in JSON or YAML.

📣
Declarative syntax
You define 'what'; CloudFormation handles 'how'.
♻️
Template reusability
The same file deploys dev, staging and production.
↩️
Automated rollbacks
A failed deployment reverts, instead of leaving half-built infrastructure.

Chapter 10 · Why bother

Using parameters

Parameters let you pass input values into the template during stack creation.

🌍
Flexibility
Different values for different environments, from one file.
♻️
Reusability
The same template works across projects.
🔐
Security
Sensitive inputs stay out of the committed template.
Parameters: InstanceType: Type: String Default: t3.micro AllowedValues: [t3.micro, t3.small, t3.medium] Resources: WebServer: Type: AWS::EC2::Instance Properties: InstanceType: !Ref InstanceType

Chapter 11 · What comes back

Outputs

Outputs let you return information about the resources that were created.

🔗 Share values with other stacks
VPC ID, Security Group ID — so a networking stack can feed an application stack.
👀 Display useful info
EC2 instance IP, DNS name — the facts a human or script needs right after deployment.
Outputs: InstancePublicIP: Description: Public IP of Web Server Value: !GetAtt EnduroWebServer.PublicIp VpcId: Description: VPC for other stacks to import Value: !Ref EnduroVPC Export: Name: !Sub "${AWS::StackName}-VpcId"
💡 !Ref returns the resource itself (usually its ID). !GetAtt reaches inside it for a specific attribute — like a public IP or DNS name.

Practical · Your first template

Lab: "Hello Bucket"

Write a simple IaC template and deploy it to AWS to see automation in action.

1 · Write the code
Create s3_bucket.yaml defining a simple S3 Bucket resource.
2 · Deploy
Upload the template to the CloudFormation console.
3 · Verify
Watch AWS provision it, then check S3 to prove it exists.
4 · Update
Add a Tag and update the stack — IaC managing change safely.
# s3_bucket.yaml — the whole thing Resources: MyFirstBucket: Type: AWS::S3::Bucket Properties: BucketName: my-first-iac-bucket-2026 Tags: - Key: Owner Value: Student
