Chapter 02 · The muscle

What is the data plane?

💪

Think of the data plane as the muscle of the network. It doesn't decide where a packet goes; it just follows orders — incredibly fast, at line speed. It handles the heavy lifting: forwarding, dropping bad traffic, and managing queues.

Handles and forwards packets from source to destination
Executes forwarding instructions set by the control plane
Operates at very high speed — performance-critical
Typically stateless — makes no routing decisions
In simple terms: the data plane moves packets.
Chapter 03 · Per-packet work

Data plane responsibilities

On every single packet: check the headers against the flow table, then act. If the rule says forward to port 3, it forwards. If the traffic is unauthorised, it drops it immediately.

Chapter 04 · The brain

What is the control plane?

🧠

If the data plane is the muscle, the control plane is the brain. It maintains a map of the entire network topology and answers the hard questions — where is this user allowed to go?, what do we do if this fibre line gets cut? — then pushes those decisions down to the switches.

Chapter 08 · The brain and its language

The controller & OpenFlow

🎛️ Role of the SDN controller

Because it sees the whole network, the controller makes smarter routing decisions than any single isolated router could.

• The central control plane and decision-making authority
• Maintains network-wide visibility
• Computes rules and distributes them to devices
• Serves as a policy enforcement engine
• Installs and updates forwarding rules in the data plane
📡 OpenFlow — the language

OpenFlow isn't SDN itself; it's the tool that makes SDN possible. Forwarding behaviour used to be locked inside proprietary vendor firmware — OpenFlow opens it up so a central controller can write the forwarding table directly.

• Direct communication between control and data planes
• Lets an external controller program how devices handle traffic
• Replaces fixed vendor-specific firmware with programmable behaviour
• Installs, modifies and removes forwarding rules in switches
• Collects statistics about flows and device behaviour
💡 This is why controllers matter — and why every other device in the network should be OpenFlow reference compatible. (Goransson et al., 2017, p. 89)
Chapter 09 · Inside the hardware

Flow tables & flow entries

OpenFlow creates flow tables inside the switch. Think of one as a spreadsheet for packets: the switch checks a packet against the table, finds a match, and executes the action immediately.
