Chapter 03 · The ground we're defending

Edge locations & key concerns

📍 Edge locations
A global network of data centres closer to end users — faster content, lower latency, more responsive apps.
🔒 Built-in protection
Part of AWS global infrastructure — encryption, access controls and physical security apply there too.
⚙️ Managed services
CloudFront and IoT Greengrass let you deploy, manage and secure workloads close to users and devices.
⚠️ The three concerns
Distributed attack surface — many locations, often with less physical control than a central data centre; data in transit between edge and cloud can be exposed.
Secure content delivery — encryption and access control keep confidentiality, integrity and availability, especially for streaming, real-time analytics and autonomous systems.
Security vs responsiveness — protection must be strong without adding latency; the whole point of the edge is speed.

Chapter 08 · Who secures what

Compliance & shared responsibility

☁️ AWS — security OF the cloud
Secures the underlying cloud infrastructure: facilities and edge locations, hardware, the global network, and the services themselves.
🧑‍💻 Customer — security IN the cloud
Secures your data, applications and configurations: encryption, access management, data retention, and meeting security and regulatory requirements.
🌍 Data residency & compliance: AWS provides services and controls so organisations can manage where data is stored and processed, according to the regulations that apply to them.

Session wrap-up

Many layers, one consistent approach

🔒 Why edge security

Protects data processed near users and devices, keeps mission-critical apps available, and secures devices, networks and applications.

🧰 AWS tools

Encryption, DDoS protection, access control, monitoring and automated incident response — CloudFront, Shield, WAF, GuardDuty, KMS, ACM.

🧅 Defence in depth

Multiple layers instead of one control — if one layer is bypassed, the next still protects the system.
